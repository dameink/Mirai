- Проверено в отдельном Python 3.12.14: 61 серверный тест на SQLite; 60 на PostgreSQL 18.6, один SQLite-специфичный тест пропущен. pip check проходит. Старый локальный venv Python 3.9 не подходит для обновлённых зависимостей; создать новый на Python 3.12.

Сообщения пользователей, токены, query-параметры и строки исключений не пишутся этим журналом. Клиент получает X-Request-ID для сопоставления с журналом. Проверены скрытие приватных данных и откат транзакции после внутреннего сбоя.
- Ошибки SQLAlchemy возвращают нейтральный ответ 503; включена проверка соединения перед его повторным использованием и скрытие SQL-параметров.
- Резервное копирование публикует только успешно созданный и проверенный dump, не перезаписывает существующий файл, очищает временные файлы при сбое. 2 отдельные проверки ошибок копирования прошли.
- В отдельном временном PostgreSQL 18.6 создана и восстановлена копия. Числа строк и хеши данных совпали во всех 17 таблицах, включая отдельные Unicode/JSON-данные. Схема: 0004_push_delivery. Рабочая Neon не изменялась. Отчёт: postgres-recovery-result.json.
- Мобильные typecheck, lint и 27 тестов проходят. Исходники APK не менялись, новая сборка для этих серверных исправлений не требуется.
- npm audit всё ещё сообщает 21 high-запись, относящуюся к двум исходным advisories braces/node-forge. Существующие локальные исправления проходят проверки; это не нулевой отчёт npm audit.

## Как повторить

Python 3.12: установить requirements-dev.txt с ограничениями requirements.lock. Затем из корня выполнить `python -m pytest tests -q`.

Для восстановления добавить бинарники PostgreSQL 18 в PATH и выполнить `python core/verify_postgres_recovery.py`. Скрипт использует только собственную временную локальную базу и останавливает её после проверки.
